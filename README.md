# Project-Dentsu-media_analytics_pipeline

## Setup
1. Place raw data files in `data/raw/`:
   - meta_ads_daily.csv
   - google_ads_daily.json
   - store_visits.csv
   - campaign_metadata.csv
2. Run `python run_pipeline.py`
3. Database will be created at `data/pipeline.db`









media_analytics_pipeline/
├── README.md                       # setup, design decisions, "with more time" section
├── .gitignore                      # Python artifacts, logs, etc.
├── requirements.txt                # empty or stdlib-only note
├── run_pipeline.py                 # single entry point, orchestrates everything
├── config.py                       # file paths, constants, business rules (thresholds, mappings)
│
├── data/
│   ├── raw/                        # untouched source files (Meta CSV, Google JSON, visits CSV, metadata CSV)
│   ├── staged/                     # cleaned, typed, validated, still 1:1 with source grain
│   └── pipeline.db                 # SQLite DB, modeled/analytics layer lives here
│
├── src/
│   ├── __init__.py
│   ├── extract.py                  # read raw files → pandas/dicts, format-specific parsing only
│   ├── transform.py                # cleaning, type coercion, dedup, validation rules
│   ├── load.py                     # staged → SQLite (schema creation, upserts)
│   ├── models.py                   # SQL DDL as strings/constants, or a schema.sql file
│   └── quality.py                  # DQ checks + a lightweight quality log/report
│
├── sql/
│   ├── schema.sql                  # DDL for staged + modeled tables, kept out of Python for reviewability
│   └── analysis_queries.sql        # the 4 business questions as named, commented queries
│
├── tests/
│   └── test_transform.py           # a handful of unit tests on the trickiest transform logic
│
├── logs/
│   └── pipeline_run.log            # basic run log, shows you think about observability
│
└── outputs/
    └── answers.md or .csv          # the 4 business question results, generated by run_pipeline.py
